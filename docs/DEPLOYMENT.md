# Deployment (free tier)

The app runs for free on four services, all set up from their websites:

| Part | Service (free plan) | What runs there |
|---|---|---|
| Website | **Vercel** Hobby | The Next.js app. It forwards `/api/*` to Render, so the browser sees one site and the login cookie stays first-party. |
| API + background worker | **Render** free web service | One Docker container: migrations, then the RQ worker and the API together (`apps/api/scripts/start-all.sh`). |
| Database | **Neon** free | Postgres with pgvector. Uploaded resumes are stored here too (`STORAGE_BACKEND=database`), because Render's free disk is wiped on every restart. |
| Redis | **Upstash** free | The job queue and rate limits. |

What to expect on free plans:

- **Render sleeps after 15 minutes without visits.** The first visit after that takes 30–60 seconds
  while it wakes. If a page shows an error then, wait a moment and refresh. Background work
  (searches, imports, resume parsing) only runs while it's awake; the app checks progress every
  couple of seconds while you wait, which keeps it awake.
- **Neon gives 0.5 GB.** `JOB_RETENTION_DAYS=45` deletes jobs not seen for 45 days, but never one
  you applied to or used for a tailored resume or cover letter.
- **Render allows 512 MB of memory.** The API and worker use about 300 MB together
  (`WORKER_NO_FORK=true` avoids a second process per job).

## Before you start

1. **New keys.** Create a new Gemini API key (aistudio.google.com) and, if you can, new Adzuna
   keys. The old ones were shared in a chat, so don't use them in production. Delete the old
   Gemini key once the new one works.
2. **A private GitHub repository** with this code. Render and Vercel deploy from GitHub and
   redeploy on every push. `.env` and your resume PDF are git-ignored; check that `git status`
   doesn't list them before you push.

## 1. Neon (database)

1. Sign up at neon.tech and create a project. Pick a region near you (for India: AWS Asia Pacific,
   Singapore).
2. On the project dashboard, open **Connect**, turn **Connection pooling off**, and copy the
   connection string (`postgresql://…neon.tech/neondb?sslmode=require…`). The pooled string
   doesn't work with this app's database driver.

The app creates its tables and the pgvector extension itself on first start.

## 2. Upstash (Redis)

1. Sign up at upstash.com and create a **Redis** database in the region closest to Render's (for
   Singapore: `ap-southeast-1`).
2. Copy the **Redis URL** that starts with `rediss://` (with two s's: TLS).

## 3. Render (API and worker)

1. Sign up at render.com with GitHub. Choose **New → Blueprint** and select your repository.
   Render reads `render.yaml` and proposes one free web service, `jobcrm-api`.
2. Choose a region (Singapore for India), then fill in the values it asks for:

   | Variable | Value |
   |---|---|
   | `DATABASE_URL` | the Neon connection string |
   | `REDIS_URL` | the Upstash `rediss://` URL |
   | `ALLOWED_SIGNUP_EMAILS` | your email: the only address that can register |
   | `CORS_ORIGINS` | your Vercel address, once you have it (step 4), e.g. `https://jobcrm.vercel.app` |
   | `GEMINI_API_KEY` | your new Gemini key |
   | `ADZUNA_APP_ID`, `ADZUNA_APP_KEY` | your Adzuna keys |

   `JWT_SECRET` is generated by Render. The rest (`ENVIRONMENT=production`, secure cookies,
   database storage, job retention) comes from `render.yaml`.
3. Deploy. When it's live, open `https://<your-service>.onrender.com/api/health`. It should show
   `{"status":"ok","database":"ok","redis":"ok"}`.

The API refuses to start in production without secure cookies and either
`ALLOWED_SIGNUP_EMAILS` or `ALLOW_REGISTRATION=false`. The error is in Render's logs.

## 4. Vercel (website)

1. Sign up at vercel.com with GitHub and **Add New → Project** from your repository.
2. Set **Root Directory** to `apps/web` (framework: Next.js).
3. Add environment variables:

   | Variable | Value |
   |---|---|
   | `API_ORIGIN` | `https://<your-service>.onrender.com` (no trailing slash) |
   | `NEXT_PUBLIC_API_URL` | `/` |

4. Deploy, then put the Vercel address into `CORS_ORIGINS` on Render (step 3).

## 5. First use

1. Open your Vercel address and register with the email from `ALLOWED_SIGNUP_EMAILS`.
2. In **Settings**, turn on AI processing if you want Gemini to read your resume and posts.
3. Upload your resume, check the profile, and run a search.

## Updating

Push to GitHub: Render and Vercel rebuild automatically. Database migrations run on every API
start.

## Troubleshooting

- **The first page load fails or hangs:** Render was asleep. Wait up to a minute and refresh.
- **"Registration is disabled":** the email doesn't match `ALLOWED_SIGNUP_EMAILS` exactly.
- **Logged out on every request / CSRF errors:** `NEXT_PUBLIC_API_URL` must be `/` on Vercel, so
  the browser only talks to the Vercel address. Redeploy Vercel after changing it (it's read at
  build time).
- **Health shows `"database": "error"`:** use Neon's non-pooled connection string.
- **Out of memory in Render's logs:** check `WORKER_NO_FORK=true` is set.
- **A resume upload fails through the website:** keep the file under 4 MB.

## Running the same setup locally

The container can run exactly as on Render:

```bash
docker run --rm -p 8001:8001 -e PORT=8001 -e STORAGE_BACKEND=database -e WORKER_NO_FORK=true \
  -e DATABASE_URL=… -e REDIS_URL=… -e JWT_SECRET=… --entrypoint ./scripts/start-all.sh jobcrm-api
```

and the website with `API_ORIGIN=http://localhost:8001 NEXT_PUBLIC_API_URL=/ npx next build &&
npx next start`.
